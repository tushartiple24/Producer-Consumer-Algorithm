    Why this is a race condition
    
          
    Two consumers can read the same shared state before either writes the update. The final result depends on thread interleaving. A mutex makes the read–check–write sequence one critical section, so only one worker can inspect and modify the shared resource at a time.
    
          
    
            
    UnsafeBoth workers read 1 and both complete a purchase: 2 tickets sold from a stock of 1 (lost update).
    
            
    SafeOne worker purchases the last ticket; the other waits for the mutex, then observes 0 and is rejected.
    
          
    
          
    Not a race condition: the five extra clients that wait when the 10-slot buffer is full. They hit the bounded-buffer condition and must block, retry or be rejected. A race condition occurs separately, when concurrent workers touch shared application state without synchronization.
    
        
    
      
    
    
    

    
    
      
    03 · THEORY
    
      
    Concept map
    

      
    
        
    
          
        
    
        
    Follow the numbers ①–⑨: requests are produced ①, inserted into the bounded buffer ②, removed ③ and processed by consumers, with blocking ④⑤ when the buffer is full or empty, mutexes guarding the queue and the ticket resource, and a race condition ⑨ possible when the resource lock is off. The same flow runs live in the simulation above.
    
      
    

      
    
        
    ① Producer
    A client thread that generates an HTTP-like request and tries to place it into the bounded request queue.
    
        
    ② Bounded buffer
    A shared request queue with fixed capacity (10 by default). Full and empty states make threads block.
    
        
    ③ Consumer
    A server worker thread that removes a request from the queue, processes it and sends the response.
    
        
    ④⑤ Semaphore
    A counter with blocking wait/signal. empty counts free slots (starts at 10) and full counts queued requests (starts at 0).
    
        
    Mutex
    A lock giving one thread at a time access. It guards the queue itself and, separately, the shared application resource.
    
        
    Critical section
    Code that touches shared state and must not run concurrently, such as queue insert/remove or the ticket read–check–write.
    
        
    ④ Buffer full
    All slots are occupied. Producers block on empty until a consumer frees a slot. This is flow control, not a race condition.
    
        
    ⑤ Buffer empty
    No pending requests. Consumers block on full until a producer inserts one.
    
        
    ⑨ Race condition
    The result depends on thread timing because shared state is accessed concurrently without synchronization (for example, a lost update).
    
        
    Mutual exclusion
    The guarantee that at most one thread is inside a critical section at a time, provided by the mutex.
